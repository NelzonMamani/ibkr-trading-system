# E23 — Truth Precedence & Global Coherence Rules
Last updated: 2026-02-13

## Core Principle: One Platform, One Truth Surface
The platform must expose a single coherent view of:
- run modes
- risk permissions
- lifecycle states
- contract responsibilities
- strategy interfaces
- verification authority
- readiness verdict

E23 defines the precedence order used to reconcile conflicts.

## Truth Precedence Order (Authoritative)
When artifacts conflict, precedence is:

1) System Law / Constitution (immutable invariants)
2) Catalogue Governance Bundles (E*/M*/P* intent and invariants)
3) Verification Authority Outputs (M5) + Audit Evidence (M7)
4) Runtime Reality (code behavior as proven by deterministic runs)
5) Legacy/compat artifacts (allowed only as compatibility shims)

Any artifact that conflicts with a higher-precedence truth is globally tagged:
- SUPERSEDED (kept for history; not authoritative)
- DEPRECATED (still referenced; must not be extended)
- IGNORE (harmful to coherence; must not influence runtime)
- COMPAT_ONLY (allowed solely for backward compatibility)

## Global Coherence Rules (must hold)
1) Canonical Run Modes
   - Canonical: SIM / PAPER / READ_ONLY / LIVE
   - Aliases may exist, but must normalize to canonical modes and must not appear as canonical in global state.

2) Authority Separation
   - Scanner is mechanical discovery only.
   - Strategy Policy owns stock-selection logic (gates, exclusions, pillars), unless catalogue governance explicitly states otherwise.
   - Risk Engine is the ultimate permissioning authority in LIVE and PAPER execution contexts.

3) No Silent Drift
   - If two artifacts disagree, E23 must emit an explicit reconciliation decision into a ledger.
   - E23 must regenerate global docs so stale/contradictory truth cannot persist.

4) Evidence-Backed Truth
   - Any "CERTIFIED/VERIFIED" claim must have evidence pointers generated by E23.
   - Evidence must be reproducible via a command captured in the report.
