# Opt-in broad RSS research

Use `scripts/verify_news_discovery.py --profile broad_rss_research_v1` with `--company-name` for one ticker or `--candidates-file` for a list of full `NewsCandidate` identities. Every issuer requires a nonempty company name; aliases, exchange, market, region and metadata pass through the existing canonical issuer relevance checks. The default remains `standalone_research_v1` with FAST_TRADING/PREP_EXTENDED. The broad profile exclusively selects BROAD_RSS_RESEARCH, reading the 161 distinct URLs in `verified_rss.txt` through its existing loader. This catalogue name is historical: current availability has not been verified. No provider requests were made to implement this capability.

The canonical service makes one batch acquisition via `BatchRssNewsIntelligenceProvider`, the existing fetcher, four-worker scheduler, bounded timeouts/deadlines and lifecycle cleanup. Each distinct feed is fetched once per acquisition batch, regardless of ticker count. Broad research uses one research tier and the requested total allocation; it does not change operational tier ordering, budgets, freshness or mandatory catalyst policy. The loader is source membership, not a retrieval engine. W01 ownership remains: canonical service/store own acquisition and persistence; standalone lookup is a request/report view; adapter, fetcher, relevance and lifecycle are legitimate layers. The dated scanner delegate and `data/news/news_provider.py` compatibility exports remain. Caller tracing found no additional demonstrated redundant implementation to delete in this path.

Per-symbol `research_observations` reports separately:

- Observed parsed-feed entry counts (shared across the batch), unknown count sources, entries examined and issuer-match observations. Matches count only entries with acceptable publication times within the requested window that pass the issuer matcher. Feed counts can include late parsed responses that the acquisition did not examine; cleanup does not admit late articles.
- Distinct retained articles and repeated observations of article identity: normalized headline + publisher label + exact URL, with publication time additionally distinguishing URL-less articles. URL case is preserved.
- Repeated exact normalized headlines across different feed-provided publisher labels. Every recorded observation retains publisher, URL, feed URL and original parsed publication time in UTC. Similar headlines are not grouped. A group is not proof of identical events, syndication or independent publishers.
- Failures, unfinished and unattempted source rows, including reasons, timeouts and deadline facts. Coverage can be partial even with matching articles; an empty incomplete acquisition cannot be completed-no-match.

Retained articles are bounded by `--max-items` (1–100 per issuer). Unlike trading retrieval, reaching this cap does not stop research source scheduling or matching. Further distinct observations are counted as article-limit exclusions. Observation records are separately bounded at 1,000 per issuer per acquisition, with an explicit truncated-record count and lower-bound repetition flag. Processing remains bounded by the existing source/tier/stage deadlines; partially examined feeds are marked partial with `processing_truncated=true`. These limits mean this is not a worldwide completeness claim.

The canonical evidence store persists the acquisition report with its existing issuer/settings/source-URL fingerprint and cadence semantics. Each persisted issuer acquisition contains only that issuer's observation records. Cache-only replay preserves historical acquisition counts and times; it is not a fresh source check. Retained articles can additionally contain revalidated evidence from earlier cache acquisitions; observation grouping is explicitly scoped to the saved acquisition. Missing/incompatible/expired acquisition coverage remains unknown. No new cache authority exists.

Research evidence and grouping do not qualify catalysts. Source availability and trading acceptance need separate future evidence. PAPER_READY=NO; PAPER_READINESS_GATE=FAIL.

## Later Windows lookup

The final engineering response supplies one complete PowerShell block bound to the reviewed source head. Run it from the prepared Windows checkout after that head is present. It checks the exact source/interpreter and imports, requires a new output directory, writes identities and uses isolated canonical cache/results. Human output and JSON are both retained. The exact shareable JSON path is printed. The command is prepared only, not executed in the cloud.

Flags for the prepared lookup: `--profile broad_rss_research_v1 --provider rss --lookback-hours 24 --budget-seconds 120 --request-timeout-seconds 5 --cleanup-seconds 10 --max-items 100 --cache-mode refresh`. The supervised wall limit is 140 seconds (10 startup + 120 retrieval + 10 cleanup), followed only by the existing bounded termination allowances if needed. Requests scalar timeouts are connect/read waits; acquisition and process deadlines provide separate wall bounds. Read per-source outcomes and cleanup even if the command exits successfully: process success is not source coverage or trading acceptance.
