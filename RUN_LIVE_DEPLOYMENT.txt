TITLE: LIVE_DEPLOYMENT_BLOCK — FIRST REAL TRADE (CONTROLLED, SAFE, VERIFIED)
FILE: RUN_LIVE_DEPLOYMENT.txt

OBJECTIVE
Transition from PAPER → LIVE and execute the first real trade under strict control.
This is a controlled activation, NOT full automation.

IMPORTANT REPO-ALIGNED NOTES
- This system resolves execution authority from runtime mode + safety rules, so you must verify the startup banner instead of trusting raw env vars alone.
- For a first live trade, use the built-in `MICRO` risk profile and `IBKR_MAX_ORDERS_PER_RUN=1`. That combination is the repo-native way to force one-share / one-order behavior.
- In LIVE mode, port 7496 is mandatory. PAPER/SIM use 7497.
- LIVE-like modes force `EVENT_REPLAY_MODE=OFF` during resolution.

────────────────────────────────────────────────────────
STEP 0 — IBKR PRE-CHECK (MANDATORY — DO NOT SKIP)
────────────────────────────────────────────────────────
Ensure all of the following are true before starting:

✔ IBKR TWS or IB Gateway is RUNNING
✔ Correct environment target:
   - LIVE → port 7496
   - PAPER/SIM → port 7497
   - Do NOT use 7497 for this run
✔ TWS / Gateway API settings:
   - "Enable ActiveX and Socket Clients" = ON
   - "Read-Only API" = OFF
   - "Allow connections from localhost only" = ON
✔ Account has buying power
✔ Market is open, or you intentionally support the session you are trading
✔ You are ready to stop immediately if behavior is unexpected

────────────────────────────────────────────────────────
STEP 3 — RISK CONSTRAINTS (CRITICAL SAFETY LAYER)
────────────────────────────────────────────────────────
Use the repo-native micro guardrails for the first live trade:

$env:RISK_PROFILE="MICRO"
$env:IBKR_MAX_ORDERS_PER_RUN="1"
$env:RISK_MAX_OPEN_POSITIONS="1"
$env:WATCHLIST_MAX_SYMBOLS_PER_STRATEGY="15"
$env:FOCUS_MAX_SYMBOLS_PER_STRATEGY="5"

What this means in practice:
- `RISK_PROFILE=MICRO` clamps order size to 1 share
- `IBKR_MAX_ORDERS_PER_RUN=1` prevents more than one submitted IBKR order in the run
- `RISK_MAX_OPEN_POSITIONS=1` blocks concurrent position expansion
- `MICRO` also disables scaling / adds

Do NOT rely on non-native variables such as:
- `MAX_SHARES_PER_ORDER`
- `MAX_DOLLAR_RISK_PER_TRADE`
- `MAX_POSITIONS`
- `FORCE_SINGLE_TRADE`

Those names are not the primary repo-enforced controls for this codebase.

STEP 7 — WHAT YOU MUST SEE (LIVE CHECKPOINTS)
────────────────────────────────────────────────────────
1. CONNECTION / STARTUP BANNER
   Expect startup output showing:
   - RUN_MODE resolved to LIVE
   - EVENT_REPLAY_MODE resolved to OFF
   - IBKR_PORT = 7496
   - IBKR_MARKET_DATA_TYPE = DELAYED or LIVE

   If port resolves to 7497 → STOP immediately.

2. EXECUTION GATE
   Expect the runtime banner to show:
   - EXECUTION_ENABLED: True
   - IBKR_READONLY_ENABLED: False
   - IBKR_ORDER_TRANSLATION_ENABLED: True
   - IBKR_ORDER_SUBMISSION_ENABLED: True

   If any of those are false → STOP.

3. STRATEGY / PIPELINE
   Expect evidence that Ross Momentum is selected and active, plus pipeline output such as:
   - watchlist / scanner summary
   - [SCANNER][WATCHLIST] ...
   - [SCANNER][FOCUS] ...
   - intent / decision activity when valid setups appear

   If there is no strategy activity, either:
   - market conditions do not qualify, or
   - filters are too strict, or
   - the strategy is not actually enabled

4. ORDER SUBMISSION (CRITICAL MOMENT)
   Expect one of the following classes of evidence:
   - order translation logs
   - execution engine submission logs
   - ORDER_SUBMITTED event / evidence
   - an order immediately visible inside TWS / Gateway

   If you see signs such as:
   - readonly mode active
   - execution hard disabled
   - order routing blocked
   - kill switch active
   then STOP immediately.

5. IBKR CONFIRMATION
   In TWS / Gateway you must see:
   ✔ exactly one order appears
   ✔ quantity = 1 share
   ✔ status = Submitted / Filled / Cancelled by your intervention

────────────────────────────────────────────────────────
FAILURE MODES (CRITICAL)
────────────────────────────────────────────────────────
NO ORDER APPEARS
→ IBKR connection, permissions, translation, submission, or qualifying-setup issue

ORDER BLOCKED
→ runtime authority, readonly, kill switch, or submission flags are still wrong

MULTIPLE ORDERS
→ stop immediately; investigate `IBKR_MAX_ORDERS_PER_RUN`, active positions, and execution guard behavior

NO INTENTS
→ market conditions not qualifying, session mismatch, or filters too strict

PORT DRIFT TO 7497
→ configuration mismatch; this is not a valid first LIVE trade run
